# Testing KNP Connect

## Overview
KNP Connect is a React + Supabase social media platform for Kisii National Polytechnic. It uses Vite as the build tool, React 18 with TypeScript, and Supabase for auth, database, and storage.

## Devin Secrets Needed
- `VITE_SUPABASE_URL` - The Supabase project URL (e.g. `https://xyz.supabase.co`)
- `VITE_SUPABASE_PUBLISHABLE_KEY` - The Supabase anon/public key

**Without these secrets, the app will crash immediately with "supabaseUrl is required" and no UI will render.** You must have these before any meaningful E2E testing.

## Local Dev Setup
1. `cd /home/ubuntu/repos/KNP-connect`
2. `npm install`
3. Create `.env` with `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`
4. `npx vite --port 5173 --host` (Vite may auto-increment port if 5173 is in use)
5. App is available at `http://localhost:5173/` (or the port Vite selects)

## Key Routes
- `/auth` - Login/signup page (public)
- `/` - Home feed (protected, redirects to /auth if not logged in)
- `/discover` - Discover page
- `/messages` - Messages list
- `/chat/:id` - Individual chat
- `/create-post` - Create a post (`?type=reel` for reel creation)
- `/reels` - Reels feed
- `/admin` - Admin panel (requires admin role)
- `/profile` - User profile
- `/edit-profile` - Edit profile

## Build & Lint
- **Build:** `npx vite build` - Should exit with code 0
- **Lint:** `npm run lint` - Has 18 pre-existing errors (mostly `@typescript-eslint/no-explicit-any`) and 8 warnings. These are in the original codebase, not from any fixes.
- **Dev server:** `npx vite --port 5173 --host`

## Testing Approach
- **Without Supabase credentials:** Can only verify build success and code compilation. No UI renders.
- **With Supabase credentials:** Can test auth flow (sign up, sign in), post creation, story creation/viewing, chat messaging, reel uploads, admin panel.

## Storage Upload Paths
The Supabase storage RLS policy requires the first folder segment to be the authenticated user's ID. Upload paths must follow this pattern:
- Posts: `{userId}/{timestamp}.{ext}`
- Stories: `{userId}/stories/{timestamp}.{ext}`
- Chat images: `{userId}/chat/{timestamp}.{ext}`

## Database Constraints
- `post_type` CHECK constraint allows: `text`, `photo`, `video`, `event`, `announcement`, `reel`
- The constraint name is `posts_post_type_check` (Postgres default naming)

## Known Issues
- The app was generated by Lovable and has some pre-existing lint issues
- Google OAuth uses a `lovable` integration that may need specific configuration
- The `@import` in CSS should precede other statements (pre-existing warning)
